# Gihyo Digital Publishingの履歴取得

対象は [Gihyo Digital Publishing](https://gihyo.jp/dp) で購入した電子書籍です。
「gihyo」「技評の電子書籍」という依頼は、このストアとして扱います。
紙の本を販売するGihyo Directとは購入先とアカウントの履歴を分け、利用者が明示していない別ストアへ対象を広げません。
既存の購入先IDを再利用し、初めて登録する場合は `source.id: gihyo-dp`、`source.name: Gihyo Digital Publishing`、`source.kind: online` とします。

## マイページを開く

1. Codexが接続済みのChromeでストアを開き、ナビゲーションの「マイページ」へ進みます。公開されている入口は [マイページ](https://gihyo.jp/dp/my-page) です。
2. ログインが必要なら利用者へ操作を案内し、認証後に購入済みの書籍一覧を読みます。公式の[マイページの説明](https://gihyo.jp/dp/help/buy/mypage)では、購入した書籍を一覧で管理できることが案内されています。
3. 一覧の続きを確認し、依頼期間に該当する入手を取得します。購入日のない項目は、[共通の期間と取得範囲の扱い](../collection.md#購入済み一覧と取得範囲)に従います。

販売中のストア一覧、サンプル、公開されている書籍紹介を、購入の根拠には使いません。
書籍を選択すると形式を確認できる場合がありますが、PDFやEPUBを実際にダウンロードする必要はありません。
ダウンロードや外部ストレージへの保存を開始するボタンは押しません。

## 記録する内容

| 項目 | 読み取り方 |
| --- | --- |
| 書名と版 | マイページの対象項目から特定し、必要な書誌情報だけ対象の商品ページで補います。 |
| 形態とファイル形式 | `book.format: digital`。PDFとEPUBの両方を確認できた場合は `file_formats: ["pdf", "epub"]` とし、同じ入手で利用できる形式を一つにまとめます。 |
| 購入日 | 購入日と確認できた表示だけを使います。書籍の発売日やデータの更新日では補いません。 |
| 入手の根拠 | マイページの一覧は `evidence.kind: owned_list`。一覧の参照先と観測日時を記録します。 |
| ISBN | 購入した電子版と対応する値だけを使い、分からなければ `null` にします。 |

対象の電子書籍URLが `/dp/ebook/年/ISBN` の形なら、そのISBNをチェック桁まで検証して使います。
商品IDはハイフンを除いた同じ値とし、`book.identifiers` に `namespace: gihyo-dp`、`scope: gihyo.jp/dp` として保存します。
リンク先の紙版には別のISBNがあるため、電子版の値と混同しません。

公式の[取得方法の説明](https://gihyo.jp/dp/help/reading/contents)は、一冊に対して形式ごとの取得先を選ぶ構成です。
PDFとEPUBのボタンを二冊分に数えず、一つの入手記録として扱います。
データ更新や再ダウンロードも、追加購入として登録しません。

## 重複を防ぐ識別

アカウント内の購入済み項目を継続して識別できるIDが実際に確認できた場合だけ、`external.holding_id` を使います。
商品IDやISBNしか分からない場合、それを購入済み項目のIDへ読み替えません。
個人用のダウンロードURLや認証トークンをキーや根拠へ保存しません。
注文番号と明細が確認できる場合は共通の注文識別規則を使い、識別できない項目は確認対象へ残します。

一覧を再取得する場合は、以前と同じ購入先ID、アカウント識別名、入手のキーを使います。
表示順やページ番号、対応形式の追加でキーを変えません。

マイページで書籍一覧を読み終えても、購入日や過去の取引を確認できなければ購入履歴全体を確認済みにはしません。
