# O’Reilly Japan Ebook Storeの履歴取得

対象は [O’Reilly Japan Ebook Store](https://www.oreilly.co.jp/ebook/) で購入した電子書籍です。
「O’Reilly」「oreilly」という依頼は、このストアとして扱います。
oreilly.comの定額学習サービスで閲覧できる本は、買い切りの購入に含めません。
既存の購入先IDを再利用し、初めて登録する場合は `source.id: oreilly-japan`、`source.name: O’Reilly Japan Ebook Store`、`source.kind: online` とします。

## 購入済み一覧を開く

1. Codexが接続済みのChromeでストアを開き、既存のログイン状態を使います。ログインが必要なら、その場で利用者へ操作を案内します。
2. サイトのナビゲーションから、ログイン後の「購入済みの商品」に相当する一覧へ進みます。公式の[利用案内](https://www.oreilly.co.jp/ebook/help.html)では、購入後の商品をこの一覧から再取得できることが説明されています。
3. 一覧の続きを最後まで確認し、依頼期間に該当する入手を取得します。日付が分からない一覧は、[共通の期間と取得範囲の扱い](../collection.md#購入済み一覧と取得範囲)に従います。

ストアの「All Titles」は販売中の商品一覧で、購入の根拠には使いません。
ログイン後の一覧の見出しや表示内容を確認してから取得します。
PDFやEPUBの本体のダウンロード、Dropboxへの転送、過去アカウントの統合は取り込みに不要です。

## 記録する内容

| 項目 | 読み取り方 |
| --- | --- |
| 書名と版 | 購入済み一覧の対象行を起点にし、必要な書誌情報だけ商品ページで補います。 |
| 形態とファイル形式 | Ebookの入手は `book.format: digital`。その購入で提供されると確認できた形式だけ、`pdf` や `epub` などの入力値で `file_formats` に入れます。 |
| 購入日 | 購入日として表示された値だけを使います。発売日、データ更新日、取得した日を購入日にしません。 |
| 入手の根拠 | 購入済み一覧の観測は `evidence.kind: owned_list`。一覧の参照先と観測日時を記録します。 |
| ISBN | 購入した電子版との対応を確認できた場合だけ使います。紙版のISBNを、書名が同じという理由で転用しません。 |

商品ページの `/books/` の後の13桁の番号は、`book.identifiers` に `namespace: oreilly-japan`、`scope: oreilly.co.jp` として保存できます。
商品ページが紙と電子を併売していても、購入済みEbookの形態は `digital` のままです。
この商品IDを入手のIDには使いません。

PDFとEPUBが一つの購入に付いていれば、一件の入手記録にまとめます。
形式ごとのリンク、ダウンロードし直した記録、差し替えられたファイルを別の購入として数えません。
形式が分からない場合も、ファイルを取得して調べる必要はありません。

## 重複を防ぐ識別

購入済みの項目そのものを識別する安定したIDを実際の画面で確認できた場合だけ、`external.holding_id` を使います。
ISBN、商品URL、ファイル名、署名付きダウンロードURLを、そのまま入手のIDにはしません。
注文番号と明細を取得できる画面がある場合は、共通の注文識別規則を使います。
どちらも確認できない項目は、不明なIDを作らず確認対象として取り込みます。

購入済み一覧だけでは過去の取引回数やキャンセルまで確認できないことがあるため、一覧を読み終えたことと購入履歴全体の確認完了を区別します。
再取り込みでは、既存記録と同じ購入先ID、アカウント識別名、入手のキーを保ちます。
